# 字幕脱敏审校台（Subtitle Mask Console）

本机完成的 WebVTT 字幕正则脱敏工具：粘贴带时间码的 VTT → 配置姓名 / 电话 / 证件等正则规则 →
按优先级合并重叠命中并保留原始时间轴 → **实体决策**（按规则 + NFKC 归一实体一次设为始终应用 /
始终保留，新命中自动继承）与**逐条例外**（显式覆盖实体决定，可清除恢复继承）→ 确认后导出
**新 VTT** 与 **JSON 审计文件**。每条规则可在**固定模板**与**稳定化名**两种替换模式间切换；
稳定化名让同一实体跨字幕始终使用同一编号化名，编号持久不复用，并支持手动改名。规则还可开启
**跨 cue 连续扫描**：把时间相邻（间隔不超过阈值）的字幕文本拼成扫描窗口，被两条字幕断开的
敏感串也能命中，替换文本写入首条字幕、后续字幕中被覆盖字符删除。每条规则还可配置
**上下文条件**（命中前 / 命中后的上下文正则与检查字符数）：候选命中须先在所在扫描窗口取上下文
并通过条件，才进入优先级与重叠消解，被过滤的候选不会压制其他规则。导出前还有一道
**导出残留防线**：按最终状态生成候选文本后再次运行全部启用规则，用替换前后字符来源映射把二次命中
分为人工保留（仅提示）/ 替换产物 / 跨边界新命中（后两类阻断导出）。任务自动保存在
本机，刷新页面或重启服务后可恢复。

技术栈：React 18 + TypeScript + Vite（前端）、Node.js 20 + Express + TypeScript（后端）。
所有计算均在浏览器请求的本机服务中完成，**不向任何外部服务发送字幕内容**。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

依赖安装、前后端构建、服务启动均在镜像内自动完成，无需手动初始化。

启动后访问：

- 地址：<http://localhost:3000>
- 端口：容器内 `3000`，宿主机默认也是 `3000`（可用 `HOST_PORT` 修改）

停止：

```bash
docker compose down        # 保留任务数据（Docker 卷 subtitle-mask-data）
docker compose down -v     # 同时清除本机保存的任务
```

## 本地开发（不用 Docker）

要求 Node.js ≥ 20。

```bash
npm install                 # 安装全部 workspace 依赖

# 终端 1：后端（监听 3001，文件持久化到 server/data/）
npm run dev:server

# 终端 2：前端 Vite（监听 5173，/api 代理到 3001）
npm run dev:web
```

访问 <http://localhost:5173>。

生产构建与运行（服务自身托管前端静态文件，监听 3000）：

```bash
npm run build
npm start
# 打开 http://localhost:3000
```

其他命令：

```bash
npm run typecheck     # 前后端类型检查
npm run test:engine   # 脱敏引擎自测（46 项：命中/合并/例外/实体决策/时间轴/审计/稳定化名/残留防线/跨 cue 扫描/上下文条件等）
```

## 配置

无需任何必填配置。可选环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST_PORT` | `3000` | 仅 Compose 使用，宿主机映射端口（`.env` 可改） |
| `PORT` | `3000` | 后端监听端口（开发模式下脚本固定为 3001） |
| `DATA_DIR` | `./data`（Docker 中为 `/app/data`） | 任务持久化目录，单个 `job.json` 原子写入 |

## 使用流程

1. **粘贴 VTT**：将带时间码的 WebVTT 粘入左侧编辑框（可点「载入示例」体验）。
   NOTE / STYLE / REGION 块、cue id、时间行与内联标签都会保留，只替换文本。
2. **配置规则**：从内置预设一键添加（手机号、邮箱、身份证、银行卡、姓名等），或新建自定义规则。
   展开规则可在「固定模板 / 稳定化名」间切换；选稳定化名时设置化名前缀（见下）。
   需要命中被两条字幕断开的敏感串时，开启「跨 cue 连续扫描」并设置最大间隔毫秒数（见下）；
   需要只在特定上下文里命中时，填写「命中前 / 命中后」上下文正则与检查字符数（空条件不限制，
   候选先过条件再参与优先级消解；见下）。
3. **审校预览**：右侧自动计算（300ms 防抖）。命中片段高亮显示原文 → 替换结果；
   重叠命中按规则处理（见下），被吞并项以紫色「重叠抑制」提示并写入审计。
   跨 cue 命中带「跨cue」标记，同一命中在所有涉及字幕联动高亮、一键撤销。
   使用稳定化名时，左侧「化名表」列出各实体编号，可手动改名。
4. **实体决策**：左侧「实体决策」列表按「规则 + NFKC 归一实体」汇总全部命中，
   可将某实体一次设为**始终应用**或**始终保留**；决定持久化，同实体新命中自动继承。
   可按 待定 / 始终应用 / 始终保留 / 有例外 筛选并查看数量（见下）。
5. **逐条例外**：点命中片段上的「撤销 / 应用」写入该命中的显式例外（优先于实体决定）；
   带「例外」标记的命中可点「⟲ 继承」清除例外、恢复继承实体决定。顶部「全部撤销 /
   全部应用」等价于对当前全部命中批量写入目标状态。
6. **导出残留防线**：预览区自动对候选导出文本做二次扫描（随规则 / 例外变化实时重算），
   按 cue 列出可定位的问题清单（见下）；存在**替换产物 / 跨边界新命中**时导出按钮禁用，
   服务端同样拒绝导出（HTTP 409）。
7. **确认导出**：点右上「④ 确认并导出」，分别下载：
   - `desensitized-<时间戳>.vtt`：脱敏后字幕（CRLF，时间轴原样）
   - `desensitized-<时间戳>.json`：审计报告（含每条记录的决策来源与残留扫描计数）

任务在编辑时自动保存（800ms 防抖）到服务端 `data/job.json`，**刷新页面、重启容器后自动恢复**。

### 优先级与重叠合并

- 所有规则同时扫描，命中按 **优先级数值降序** 排序；数值相同取**更长匹配**，再相同按规则名。
- 贪心选择互不重叠的区间：后处理的命中若与已入选命中重叠，则被抑制（suppressed），
  仅记录到审计 JSON，不执行替换。例如身份证（80）与银行卡（75）在同一段 18 位数字上重叠时，
  身份证规则胜出。

### 跨 cue 连续扫描

字幕换行常把手机号、证件号等敏感串拆到两条相邻字幕里（如上一条结尾 `1381234`、
下一条开头 `5678`）。每条规则可独立开启**跨 cue 连续扫描**并设置**最大间隔毫秒数**
（默认 500ms）：

- **扫描窗口**：服务端把「下一条开始时间 − 上一条结束时间 ≤ 阈值」的相邻 cue 纯文本
  **直接拼接**（不加分隔符）成扫描窗口，并建立「窗口逻辑字符 → cue + 原文偏移」的映射；
  时间上重叠的 cue 同样视为相邻。间隔超过阈值的 cue 不会被拼进同一窗口，
  孤立 cue 自成单 cue 窗口（因此 cue 内部的命中不受影响）。
- **统一消解**：跨 cue 命中与单 cue 命中按同一套「优先级降序 → 更长匹配 → 规则名」
  规则消解重叠——重叠按「共享任一 cue 的任一字符」判定，被吞并的命中照常只入审计。
- **应用方式**：替换文本（模板展开或稳定化名）**整体写入首个涉及 cue**，
  后续涉及 cue 中被覆盖的字符删除；各 cue 的时间行、标识与未命中文字保持原样。
- **预览联动**：一个跨 cue 命中以同一命中键挂在所有涉及 cue 上——悬停任一片段，
  所有涉及片段联动高亮；在任一涉及 cue 上点「撤销 / 应用」即对整个命中生效。
  锚定 cue 显示替换结果，后续 cue 的被覆盖字符以删除线标示（导出时删除）。
- **状态一致**：稳定化名（同一实体同一编号化名）、实体决定（始终应用 / 始终保留）、
  逐条例外与审计记录都沿用**同一命中键**；审计记录与残留防线问题清单均记录
  **涉及 cue 列表**（`cueIndexes`）。
- **残留防线联动**：开启跨 cue 的规则在「相邻 cue 候选文本拼接窗口」上二次扫描——
  例如撤销一个跨 cue 命中后，被断开的完整敏感串仍会被发现并归类为「人工保留」（仅提示）；
  替换后跨 cue 拼出的新敏感串同样会被拦截。

预设「手机号（跨字幕连续扫描）」（默认停用）演示了该能力：间隔不超过 800ms 的
相邻字幕拼成窗口，命中后替换写入首条字幕。

### 上下文条件（命中前 / 命中后）

每条规则可在展开详情里配置**命中前上下文正则**与**命中后上下文正则**（不含首尾 `/`，
留空表示该侧不限制），并分别设置**检查字符数**：

- **判断顺序**：规则扫描出候选命中后，先在**命中所在的扫描窗口**中取紧邻命中前 / 后的
  字符作为上下文、在其中检索对应正则；候选须先通过两侧条件，**再进入**现有的
  「优先级降序 → 更长匹配 → 规则名」排序与重叠消解。因此被条件过滤掉的高优先级候选
  **不会继续压制**低优先级规则的命中（被过滤的命中不占用任何字符区间）。
- **检查字符数**：`0` = 一直取到扫描窗口边缘（不限制长度）；填 `N` 则只检查紧邻命中的
  N 个字符。非负整数，非法值回退 `0`。
- **窗口边缘按实际可用字符处理**：命中位于 cue / 窗口开头时命中前只有 0 个字符、
  位于末尾时命中后可能不足 N 个字符，均按实际长度截取，不做补齐或跨窗口延伸。
- **跨 cue 规则沿用拼接窗口**：开启跨 cue 连续扫描的规则，上下文同样在「相邻 cue 纯文本
  直接拼接」的窗口上判断——命中前上下文可跨越 cue 边界取到上一条字幕的结尾字符，
  命中后上下文同理；窗口边界（间隔超阈值处）之外的字符取不到。
- **锚定语义**：上下文正则在截取到的上下文字符串中检索（使用规则自身的 `i` / `u` / `s`
  等标志，忽略 `g`）。常用 `$` 表示条件须贴住命中（如命中前 `验证码.{0,8}$`），
  `^` 表示从命中紧邻处开始（如命中后 `^.{0,4}转`）；不加锚定则只要出现在检查范围内即通过。
- **校验与计数**：上下文正则无效时在规则编辑区行内报错（标明命中前 / 命中后），预览横幅
  同样提示，该规则不参与扫描；预览统计栏与预览区显示**上下文过滤**计数，按规则、按
  「命中前 / 命中后未通过」分别统计（同一候选两侧都未通过时两侧各计一次）。
- **残留防线一致**：导出前的二次扫描同样应用上下文条件，被条件过滤的二次候选不进入
  残留问题清单；导出审计 JSON 顶层 `contextFilters` 持久化过滤计数。
- **旧任务迁移**：旧版规则缺少 `beforePattern` / `afterPattern` / `beforeChars` /
  `afterChars` 字段时按**无条件**迁移（空正则、字符数 `0`），命中行为与旧版完全一致。

预设「手机号（仅验证码短信上下文）」（默认停用）演示了该能力：只有命中前 8 个字符内出现
「验证码」或命中后 4 个字符内出现「转」的手机号才会被脱敏。

### 实体决策与逐条例外

每个命中都按「规则 ID + 原文经 Unicode **NFKC 归一化**并**去首尾空白**」归并为实体
（与稳定化名同一套实体键，全角 / 半角、兼容字符、首尾空白差异都收敛）。最终状态按
以下优先级解析：

1. **逐条例外**：审校员对单个命中的显式「撤销 / 应用」，优先级最高；
2. **实体决定**：该实体的「始终应用 / 始终保留」，同实体的新命中（含后续新增字幕）自动继承；
3. **默认**：应用替换。

语义细节：

- 实体决定随任务**持久化**（`job.json` 与审计 JSON），刷新 / 重启后沿用；
  「待定」表示不做实体级决定。当前暂无命中的实体决定也会保留在列表中，对未来命中生效。
- 逐条操作写入的例外与继承状态一致时会自动清除（不产生冗余例外）；「实体决策」列表中
  带「例外 n」的实体可一键清除该实体全部例外、恢复继承。
- 规则变化或重叠合并后，决定与例外**只对胜出命中生效**；被抑制命中不生成例外、
  不受实体决定影响（例如对银行卡实体设了「始终保留」，其与身份证重叠被抑制时不产生任何效果，
  待身份证规则停用、银行卡成为胜出命中后才继承保留）。
- 预览、导出 VTT 与审计 JSON 始终使用**同一份最终状态**计算；审计记录逐条标注
  `decisionSource`（`default` / `entity` / `exception`），并在报告顶层持久化实体决定。

### 替换模式：固定模板 / 稳定化名

每条规则在展开详情里可切换两种替换模式，并在规则名旁显示「化名」标记：

- **固定模板**：按下方模板占位符逐次替换，每个命中各自独立。
- **稳定化名**：同一实体在所有 cue 中始终替换为**同一个编号化名**（如 `人物1`、`人物2`）。

稳定化名语义：

- **实体键**由「规则 ID + 原文经 Unicode **NFKC 归一化**并**去首尾空白**」构成，
  因此全角 / 半角（如 `１３８` ↔ `138`）、兼容字符与首尾空白差异都收敛为同一实体。
- **编号持久、只增不复用**：编号按规则独立分配，随首次命中按 cue 顺序生成；
  之后增删其他字幕、增删命中、调整撤销都**不会重排**已有编号，新实体顺延取下一个序号。
- **化名前缀**可在规则中设置（留空默认「化名」），改动前缀会联动所有仍为自动的化名；
  编号本身不变。
- **手动改名**：左下「化名表」可把任一实体改为自定义化名（如把 `人物1` 改成 `客户甲`），
  立即联动该实体**所有未撤销命中**；「恢复自动」交回 `前缀+序号`。
  前缀调整不影响已手动改名的实体。
- **逐条例外与重叠优先级语义不变**：撤销某命中仍恢复该处原文（化名保留在表中），
  化名规则与模板规则并存时同样按优先级 / 最长匹配吞并，被抑制项只入审计、不占用编号。
- 化名映射随任务自动保存并在导出审计 JSON 中持久化（含实体键、最终化名、命中状态），
  刷新 / 重启后沿用。

### 替换模板（固定模板模式）

| 占位符 | 含义 |
| --- | --- |
| `$&` | 整体命中 |
| `$1` `$2` … | 捕获组（支持 `$<name>` 命名组） |
| `$KEEP:3` | 保留命中前 3 个字符，其余打码（空白保留），如 `138****5678` |
| `$MASK:2` | 仅前 2 个字符打码 |
| `$MASKALL` | 整体打码 |
| `$RULE` | 规则名 |

正则标志中 `g` 会自动补齐；支持 `i`、`u`、`s` 等标准标志。无效正则会在界面与预览中提示，不会中断处理。

### 导出残留防线（二次扫描）

第一遍替换完成后，引擎按**当前最终状态**（实体决定 + 逐条例外）生成候选导出文本，
对每条 cue **再次运行全部启用规则**（开启跨 cue 连续扫描的规则则在相邻 cue 候选文本
拼接窗口上扫描，被断开的残留敏感串同样会被发现），并用「替换前后字符来源映射」把每个二次命中分类：

| 分类 | 判定 | 后果 |
| --- | --- | --- |
| **人工保留** | 命中不涉及替换产物，且与人工保留的原文重叠（逐条撤销 / 实体「始终保留」；含第一遍被抑制、因胜出命中被保留而复现的命中） | 仅提示，不阻断导出 |
| **替换产物** | 命中完全落在**单个**替换产物（模板展开 / 化名）内 | **阻断导出**，显示来源规则与目标规则 |
| **跨边界新命中** | 命中跨越多个来源片段（如替换删掉分隔符后两侧原文拼出敏感串），或因替换改变上下文而落在纯原文上的全新命中 | **阻断导出**，列出全部涉及区间 |

语义细节：

- 候选文本按字符标注来源：**未命中原文 / 人工保留原文 / 替换产物**（含产生它的规则）。
  二次扫描不做优先级合并——任何残留命中都会列入清单。
- **替换产物**示例：规则 A 把「朝阳路5号」替换为「某小区3号楼」，规则 B（`\d+号楼`）又命中
  产物中的「3号楼」→ 清单显示来源规则「地址脱敏」与目标规则「楼号」。
- **跨边界新命中**示例：规则删掉 `138-12345678` 中的 `-`，候选文本拼出 `13812345678`
  被手机号规则命中 → 清单列出涉及的「原文 + 替换（空）+ 原文」三个区间。
- **处理方式**：调整来源规则的替换模板 / 化名前缀，或把产生问题的命中撤销（改为人为保留）；
  人工保留的命中只提示、不阻断。
- 预览随规则、例外、实体决定、化名的每次修改**实时重算**（与预览同一防抖管线）；
  前端按 cue 分组展示问题清单，点「⌖ 定位」滚动到对应字幕并闪烁高亮。
- 存在阻断项时导出按钮禁用；服务端 `/api/export` 同步校验并返回 `409` 与问题清单，
  保证预览、导出、审计始终使用同一份最终状态。
- 审计 JSON 顶层记录 `safetyScan` 分类计数与问题清单（见下）。
